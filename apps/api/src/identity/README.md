# OIDC provider boundary

`OidcIdentityProvider` implements the provider protocol seam. The Express adapter, auth-flow coordinator, session service, and persistence ports are wired into startup when complete provider, encryption, cookie, origin, and rate-limit settings are supplied. Without provider settings, startup uses the fail-closed authenticator. This wiring is in progress and has not yet been verified for production.

The configured issuer is canonical HTTPS and discovery is performed from that exact issuer with `openid-client`. The callback URI is a fixed canonical HTTPS URL with no query or fragment. The login method accepts no redirect target and requests only `openid email profile`. Each attempt creates independent state, nonce, and PKCE verifier values, stores their transaction with a five-minute expiry, and sends the S256 challenge. Callback handling consumes the transaction once, checks its exact callback origin/path and state, then delegates code exchange and ID-token cryptographic validation to `openid-client` with the verifier, expected state, and expected nonce. It additionally checks exact issuer, audience/client ID, `azp` for multi-audience tokens, subject, nonce, and boolean `email_verified === true` before returning a minimal claim object.

The transaction handle is carried in a short-lived `__Host-` HttpOnly, Secure, SameSite=Lax cookie and cleared after callback processing. Optional invitation or bootstrap grant digests are validated and retained only inside the AES-GCM-encrypted transaction payload; raw grant secrets are never stored there. Do not put the handle, code verifier, state, nonce, authorization code, client secret, provider tokens, or raw grant secrets in logs, URLs beyond protocol-required state/nonce, browser storage, analytics, or error messages. Do not persist provider tokens. The Prisma transaction store hashes handles and consumes records once; its startup wiring has not yet been verified for production. Deployment also needs suitable access controls and narrowly scoped service credentials.

All callbacks are HTTPS-only, including local development. The repository's current local web origin is plain HTTP, so hosted login remains unavailable locally until a trusted HTTPS callback (for example, a controlled development tunnel) is configured. The provider issuer remains HTTPS in every environment; there is no HTTP issuer or callback exception.

`loadOidcProviderConfiguration` returns `null` when all provider settings are absent, allowing the surrounding app to remain fail-closed. Partial settings or unsafe URLs throw during configuration loading. The eventual composition root must treat `null` as unconfigured and must not advertise login routes as available.
